## リスクと対策

### 技術的リスク

#### 1. LLMの出力品質

**リスク**:
- 生成された旅程が非現実的（移動時間が長すぎる、営業時間外など）
- ハルシネーション（存在しないスポット）

**対策**:
- プロンプトエンジニアリング（具体例を示す）
- 検証ロジック（移動時間、営業時間のチェック）
- Web検索で実在するスポットのみ使用

#### 2. APIコスト

**リスク**:
- GPT-5のコストが予想以上
- 1旅程生成あたりのコストが高すぎる

**対策**:
- Phase 1でコスト計測
- トークン数最適化
- 必要に応じてキャッシュ活用
- レート制限（ユーザーあたり1日X回まで）

**概算**:
- GPT-5テキスト生成: $0.02/1K tokens（仮定）
- 1旅程: 約10K tokens → $0.20
- 画像生成: 4枚/旅程 × $0.04 → $0.16
- Distance Matrix: 20回 × $0.005 → $0.10
- **合計: 約$0.46/旅程**

#### 3. パフォーマンス

**リスク**:
- サブエージェント呼び出しが遅い（特に直列実行）
- 全体で1分以上かかる

**対策**:
- 並列実行の最大化
- タイムアウト設定（各サブエージェント30秒）
- ストリーミング表示で待ち時間を感じさせない

#### 4. Web検索の精度

**リスク**:
- 検索結果が不正確
- スポット情報が古い

**対策**:
- 複数ソースからの情報収集
- レビュー数・評価による信頼性判定
- 最新情報の優先（検索クエリに年を含める）

### プロジェクト管理リスク

#### 1. スコープクリープ

**リスク**:
- 機能追加の誘惑
- MVPの範囲を超える

**対策**:
- Phase 2までの範囲を厳守
- 追加アイデアは「Phase 3以降」リストに記録

#### 2. 技術的難易度

**リスク**:
- Mastraの習熟に時間がかかる
- ReActパターンの実装が複雑

**対策**:
- Phase 0で技術検証を徹底
- 公式ドキュメント・サンプルコードを活用
- 必要に応じてシンプルな実装に切り替え
